# Product Experimentation & Causal Impact Analysis

An end-to-end product data science project evaluating a simulated onboarding redesign. The project demonstrates experiment design, data-quality checks, SQL metric construction, classical A/B inference, regression adjustment, heterogeneous treatment effects, guardrail monitoring, and a difference-in-differences robustness analysis.

> The observations are reproducible synthetic data generated by code. Results are portfolio evidence, not claims about a real Coinbase experiment.

## Business question

Should a streamlined onboarding flow be launched if it improves 7-day activation without harming support-contact rate or transaction latency?

## Methods

- Pre-experiment power analysis for a two-sided proportions test
- Stable user-level random assignment with a 50/50 split
- Sample-ratio-mismatch and covariate-balance checks
- Intent-to-treat conversion lift, confidence interval, p-value, and relative lift
- OLS regression adjustment with heteroskedasticity-robust standard errors
- Heterogeneous treatment effects by device and acquisition channel
- Guardrail tests for support contacts and transaction latency
- Difference-in-differences using pre/post engagement as an observational robustness exercise
- Benjamini-Hochberg adjustment for subgroup multiple testing

## Reproduce

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
python -m experiment.generate_data
python -m experiment.analysis
pytest
```

Generated outputs are written to `outputs/`:

- `experiment_summary.json`: machine-readable decision metrics
- `subgroup_effects.csv`: device/channel treatment effects
- `metric_table.csv`: primary and guardrail results
- `experiment_report.md`: stakeholder-ready recommendation and limitations

## Interpretation

The pipeline separates statistical significance from launch judgment. A launch is recommended only when the primary activation metric improves, randomization diagnostics pass, and neither guardrail shows statistically credible harm. Subgroup estimates are treated as exploratory and corrected for multiple comparisons.

## Limitations

- Synthetic data cannot validate real customer behavior or operational effects.
- Difference-in-differences requires a parallel-trends assumption that cannot be proven from one pre-period.
- Subgroup analyses have lower power and should guide follow-up experiments, not personalized launches.
- Novelty, interference, logging changes, and long-term retention would require production monitoring.
